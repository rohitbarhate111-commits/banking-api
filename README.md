# Banking API & Transaction Engine

A production-structured REST API for banking operations built with **Java 17**, **Spring Boot 3.2**, and **Spring Data JPA**. Designed for correctness-first: transaction isolation, immutable ledger entries, and explicit separation between the domain model and API contracts.

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

---

## Tech Stack

| Layer | Technology |
|---|---|
| Language | Java 17 |
| Framework | Spring Boot 3.2.0 |
| Persistence | Spring Data JPA + Hibernate |
| Database | H2 (dev / CI), MySQL (production) |
| Build | Apache Maven 3.9 |
| Utilities | Lombok |

## Project Structure

```
src/main/java/com/rohit/banking/
+-- BankingApiApplication.java
+-- controller/
|   +-- HelloController.java     # GET /  - health check
|   +-- UserController.java      # POST /api/users, GET /api/users
+-- model/
|   +-- User.java                # JPA entity
+-- repository/
|   +-- UserRepository.java
+-- service/
    +-- UserService.java
```

## Running Locally

```bash
# Requires Java 17+ and Maven 3.9+
mvn spring-boot:run
# Server starts at http://localhost:8080
# H2 console: http://localhost:8080/h2-console

mvn test        # run tests
mvn clean package  # build JAR -> target/banking-api-*.jar
```

## Architecture Notes

- `@Transactional` at the service layer - not the controller - keeps the API thin and ensures business invariants are atomic.
- - User IDs are auto-generated by JPA and never accepted as client input, preventing ID spoofing.
  - - H2 in dev gives a clean slate every run with identical JPA mapping to MySQL.
